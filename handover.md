# HH ASSISTANT: Handover проекта (Актуально на текущий момент)

## 1. Цель проекта
Построить персонального AI-ассистента для поиска работы на hh.ru, который собирает вакансии, оценивает релевантность (cross-encoder), генерирует письма (GigaChat), отправляет отклики, выгружает переписку в PostgreSQL и анализирует ответы работодателей.

## 2. Архитектура проекта
- **API hh:** Используется `hh-applicant-tool` (мобильное API). Прямой вход через Playwright/Patchright заблокирован.
- **GigaChat:** Генерация писем через REST API. Есть защита от исчерпания токенов (переключение на `data/fixed_letter.txt`).
- **База данных:** PostgreSQL (localhost:5433, БД `hh_vacancies`).
- **Хранение данных:** JSON-файлы для вакансий, совпадений и состояния. PostgreSQL — для аналитики и чатов.

## 3. Структура проекта
- `main.py` — Главное меню (оркестратор).
- `config.py` — Интерактивная настройка `config.json` (поддерживает мультирезюме).
- `vacancy_search.py` — Сбор вакансий по ключевым словам и периодам.
- `matcher.py` — Фильтрация и оценка релевантности (Fuzzy 95% + навыки из резюме).
- `apply_via_api.py` — Отправка откликов, дедупликация.
- `check_messages.py` — Выгрузка сообщений из чатов hh в БД (безопасная многопоточность).
- `show_replies.py` — Просмотр ответов работодателей из БД.
- `sync_negotiations.py` — Синхронизация откликов (`per_page=100`).
- `shared_api.py`, `state_helper.py`, `db.py`, `save_to_db.py`, `dedupe.py` — Вспомогательные модули.

## 4. Ключевые особенности реализации
- **Мультирезюме:** `config.json` поддерживает массив `queries` для каждого резюме.
- **Матчер:** Сначала отсеивает по стоп-словам (Fuzzy 95%), целевым фразам и навыкам из резюме. Только потом запускает `cross-encoder`. (Прим: на CPU работает медленно, ~4 часа на 10к вакансий).
- **Безопасность:** В `check_messages.py` используется 3 потока и случайные задержки, чтобы не спровоцировать капчу. В `sync_negotiations.py` — пагинация по 100.
- **База данных:** Таблицы `vacancies`, `negotiations`, `messages`, `resumes`.

## 5. Как запускать (Ежедневный цикл)
1. `python main.py` → **2** (Сбор новых вакансий).
2. `python main.py` → **3** (Матчинг: только новые, т.к. `processed` не сбрасываем).
3. `python main.py` → **4** (Отправка откликов).
4. `python main.py` → **5** (Прохождение тестов: `y` - сейчас, `later` - позже, `n` - пропустить).
5. `python main.py` → **6** (Синхронизация откликов).
6. `python check_messages.py` (Выгрузка новых сообщений в БД).
7. `python show_replies.py` (Просмотр ответов HR).

## 6. Известные ограничения
- **Потолок API:** hh отдает максимум 2000 вакансий на один запрос. Решается дроблением по периодам.
- **Скорость cross-encoder:** На CPU 10 000 вакансий обрабатываются 4 часа. Не сбрасывать `processed` без острой необходимости.
- **Токены GigaChat:** Если осталось <= 1000, скрипт автоматически переключается на `data/fixed_letter.txt`.

## 7. Важные заметки
- Файл `.env` содержит ключи `GIGACHAT_AUTH_KEY`, `DB_PASSWORD` и др.
- Резюме парсится и хранится в `data/resumes/<id>.json`.
